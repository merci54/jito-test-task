# html_samples

> **Note:** the comment at the top of each file and the table below describe how a **browser** parses the sample (WHATWG HTML spec, as in Chrome and Firefox). This is **not** the expected output of `html2json`. The parser deliberately simplifies some things: for example, it does not create `html`, `head`, `body` and `tbody`, drops indentation and does not move stray content out of tables. All differences are listed in the root [README](../README.md#decisions-and-limitations). `test_samples.js` only checks that every file is parsed without an error, a hang or an invalid result.

79 files, one case per file. Browser behavior is described according to the WHATWG HTML spec (this is how Chrome and Firefox parse) for parsing a whole document, like `DOMParser` with `text/html`: html, head and body are always created, even if they are not in the markup.

The comment at the top of each file also ends up in the tree: it is a Comment node, a child of Document, before the doctype or html. The exception is `02_empty.html`, which is empty by design.

Files marked as ending at EOF (cut-off tags, comments, script) intentionally do not end with a newline.

| `04_only_text.html` | Only text, no tags at all. | html, head and body are created automatically, the text becomes the only child of body. |
| `05_no_html_head_body.html` | No html, head or body tags: only title, meta and p. | html, head and body are created implicitly: title and meta go into head, p goes into body. |

| `07_doctype_duplicate.html` | A second doctype inside body. | The second doctype is ignored completely (parse error), body contains only two p: 'before' and 'after'. |

| `09_bom.html` | The file starts with a UTF-8 BOM (U+FEFF), before this comment. | The BOM is dropped and does not end up in the text or the tree. Note: readFileSync with 'utf8' keeps it as the first character of the string. |

Everything after the end tags of body and html (only whitespace here) is appended to the end of body. |
| `11_crlf_line_endings.html` | The whole file has CRLF line endings, plus a single CR inside text. | Before parsing, CRLF and single CR are replaced with LF: p text = 'line1' LF 'line2' LF 'line3'. For textarea the first newline is dropped: 'a' LF 'b'. |
| `12_null_char.html` | A NUL character (byte 0x00) in text and in an attribute value. | NUL in normal body text is dropped: p = 'ab'. In an attribute value it is replaced with U+FFFD: title = 'x' U+FFFD 'y'. |

| `14_tag_case.html` | Tags and attributes in upper and mixed case, an end tag in a different case. | Tag and attribute names are lowercased (div, class, span), attribute values do not change ('Upper', 'Mixed'). An end tag in a different case closes the start tag. |
| `15_void_elements.html` | Void elements in every form: br, br/, br /, img, input, hr, wbr, area, base, embed, link, meta, source, track, param. | Void elements never have children or an end tag, a slash before > is simply ignored. p contains 4 text nodes and 3 br. | `16_self_closing_non_void.html` | Self-closing syntax on normal elements: div/, span/, p/. | For normal HTML elements a slash before > means nothing, the tag stays open and the following content goes inside: div -> ['inside div', span -> ['inside span', p -> 'inside p']]. |
| `17_end_tag_br_p.html` | End tags of void elements and p without an open p: /br, /p, /img. | An end br becomes a normal br. An end p without an open p creates an empty p. An end img is simply ignored. Result: div -> ['a', br, 'b', p (empty), 'cd']. |
| `18_unknown_custom_elements.html` | Unknown and custom tags: my-component, foo-bar, foo, x:y, blink. | Unknown tags become normal elements (with a hyphen it is a potential custom element), nesting is kept. x:y is just a tag name with a colon, without namespaces. |
| `19_lt_in_text.html` | A \< character in text that does not start a tag: followed by a space, a digit or >, a \<= b. | If \< is not followed by a letter, / or !, it is normal text. All six p contain exactly the text that is written, no new elements. |
| `20_end_tag_with_attributes.html` | Attributes and a slash in end tags. | Attributes and slashes in end tags are ignored (parse error), tags are closed as usual: div#outer -> span 'text', then the text 'after' in body. |
| `21_unterminated_tag_eof.html` | The file ends in the middle of a start tag (no >). | A tag cut off by the end of the file is dropped entirely. body contains only p 'before' and whitespace text. |
| `22_attr_quotes.html` | Attribute values in double quotes, single quotes and without quotes, > and quotes inside values, a newline in a value. | All three forms give a normal string. > and quotes of the other type inside quotes are part of the value: e='has > inside', f='it "quoted"', g="it's". | `23_attr_boolean_empty.html` | Attributes without a value (checked, disabled, hidden) and with an empty value. | An attribute without a value has the value '' (empty string), the same as value=''. selected=selected is a normal string 'selected'. |

| `25_attr_whitespace.html` | Spaces, tabs and newlines around = and between attributes, attributes with no space between them. | Whitespace around = and between attributes is allowed: id='spaced', class='tabs', title='newline before value'. a="1"b="2" without a space is a parse error, but all three attributes a, b, c are read. |
| `26_attr_special_names.html` | Non-standard attribute names: data-*, aria-*, @click, :class, v-on:submit.prevent, x.y, _under, #hash. | An attribute name is any characters except whitespace, /, >, = and quotes. All these names are kept as they are (lowercased). |

| `28_attr_malformed.html` | Broken attributes: a space after =, a name starting with = or a quote, attributes stuck together, a slash between attributes. | 1) a='b="x"' (spaces after = are skipped, then comes an unquoted value). 2) an attribute named '="eq-first"' with an empty value. 3) an attribute '"quoted-name"' = '1'. 4) a='1', b='', c=''. 5) a='1', b='2' (the slash is just skipped). |

| `34_unicode.html` | Cyrillic, CJK, RTL, multi-codepoint emoji (ZWJ, flag), a combining character, a zero-width space, Cyrillic in an attribute. | All characters are kept unchanged and without normalization.
